# 먹을 결심 🫪👅🧑‍🩰🐽🍤 — v4

**냉장고 재료 선택 → 보유량 입력 → 2끼/3끼 단백질 메뉴**

메인 화면에는 목표·재료·추천 버튼과 메뉴 카드만 둡니다. API 설정, 중량 기준, 계산 데이터는 접어 둔 설정에서 확인합니다.

## 실행

새 ZIP을 **별도 폴더에 풀고 pyproject.toml이 있는 폴더**에서 실행하세요. 기존 7860 앱이 켜져 있으면 그 터미널에서 Ctrl+C로 종료한 뒤 새 버전을 실행합니다.

```powershell
uv sync
```

프로젝트 `.venv`가 자동 생성되고 Python 3.12용 패키지가 설치됩니다. 명시적으로 환경부터 만들려면 `uv venv --python 3.12` 후 `uv sync`하세요. uv 설치: https://docs.astral.sh/uv/getting-started/installation/

`.env.example`을 `.env`로 복사합니다. 이미 가지고 있는 .env는 직접 새 프로젝트로 옮겨 사용하고 덮어쓰지 마세요.

```dotenv
DATA_GO_KR_SERVICE_KEY=
OPENAI_API_KEY=
OPENAI_DEFAULT_MODEL=gpt-6-luna
```

```powershell
uv run python app.py
```

표시된 http://127.0.0.1:7860/ 을 엽니다. 별도 activate 없이 프로젝트 가상환경을 사용합니다. 외부 공유는 기본적으로 꺼져 있습니다.

노트북은 `uv run jupyter lab`로 실행합니다. VS Code에서는 이 프로젝트 `.venv`를 커널로 선택하세요.

- `01_start.ipynb`: 환경 준비·실제 출처 레시피 계산·웹 UI 실행.
- `02_how_it_works.ipynb`: API 필터·RAG·LangGraph·재고 검증 원리.

## 이렇게 사용하세요

1. 체중·활동 목표·2끼/3끼를 선택합니다.
2. 계란·소고기·체다치즈·두부 중 보유 재료를 여러 개 선택합니다.
3. 표의 **보유량만** 수정합니다. 재료명과 단위는 고정되어 있습니다.
4. 소금과 식용유가 있으면 보유 체크를 켭니다. 보유하지 않은 양념은 사용하지 않습니다.
5. **오늘 식단 추천받기**를 누릅니다.

카드에는 메뉴·실제 사용할 재료·단백질·부족량·예상 열량·원문 링크가 나옵니다. 두 요리를 함께 추천한 경우 카드의 기본 목록은 합산 중량이고, 펼치면 요리별 분량이 따로 표시됩니다. 식사 횟수나 보유량을 바꾸면 이전 결과는 사라집니다. 늦게 끝난 요청이 이전 메뉴를 되살리지 않도록 입력 지문을 비교합니다.

계란 1개 가식부 50g, 치즈 1장 20g은 **수정 가능한 기본 추정치**입니다. 제품마다 다르므로 설정에서 맞춰 주세요. 원문의 모·개·큰술·꼬집을 모두 정확한 g으로 안다고 가정하지 않습니다. 소수 개수는 혼합·조리 후 계량해 나누는 방식입니다.

## 실제 레시피는 어디서 왔나요?

아래 실제 문서를 직접 확인한 재료 사실과 짧은 발췌를 `data/verified_recipes.json`에 저장했습니다. 확인일은 **2026-10-20**입니다. 임의로 만든 레시피나 테스트 문서를 RAG에 넣지 않습니다.

- [계란두부부침 — elin](https://www.10000recipe.com/recipe/6973701)
- [치즈계란말이 — 초록쿠킹쿠킹](https://www.10000recipe.com/recipe/6947410)
- [부채살스테이크 — 좋아좋아3](https://www.10000recipe.com/recipe/7021791)

지정한 만개의레시피 사이트의 넓은 검색 목록에는 재료가 많은 요리가 섞여 있었습니다. 기본 추천은 같은 사이트에서 추가 확인한 위의 간단한 요리 3개로 범위를 좁혔습니다. 원래 지정 검색 목록을 수집하는 코드는 `recipe_web.py`에 남겨 수업에서 비교할 수 있습니다. 모든 문서를 매 실행마다 새로 내려받지 않으므로 인터넷 장애에도 **실제 출처를 확인한 발췌**로 추천할 수 있습니다.

**원문과 앱 조정을 분리합니다.** 원문의 재료 목록은 그대로 보존하고, 조정량·대체 재료는 `profile`, `adjustments`에 따로 기록했습니다. 예를 들어 팬 기름을 5g/기본 배합으로 조정했으며, 이것을 원문 큰술의 정확한 환산값이라고 표시하지 않습니다. 맛소금→소금, 슬라이스치즈→선택한 체다치즈, 부채살→선택한 소고기 부위 등의 변경도 표시합니다. 사진·전체 조리법을 복제하지 않으며 전체 순서와 시간은 원문 링크에서 확인하세요.

설정의 ‘실제 레시피 원문 다시 확인’은 직접 원문을 요청합니다. 원문의 재료 구성이 바뀌면 기존 분량 표를 새 내용에 무조건 적용하지 않고, 확인일의 발췌를 사용한다고 알립니다. 사이트 차단이나 네트워크 장애 시에도 상태를 표시합니다.

## 영양정보와 식단 계산

- 공공 API: [식약처 식품영양성분DB정보 15127578](https://www.data.go.kr/data/15127578/openapi.do).
- 호출: `https://apis.data.go.kr/1471000/FoodNtrCpntDbInfo03/getFoodNtrCpntDbInq03`.
- 검색: `FOOD_NM_KR`, 일반 식품 후보를 좁히기 위한 `DB_CLASS_NM=품목대표`.
- 사용 필드: `FOOD_CD`, `FOOD_NM_KR`, `SERVING_SIZE`, `AMT_NUM3`(단백질), `AMT_NUM1`(열량).
- 쿠키·찌개·조리식품 및 다른 식품 종류를 이름으로 추가 검사하고 재료별 최대 5개만 보관합니다. 일반 두부에 순두부나 두부면을 자동 연결하지 않습니다.
- 사용한 실제 식품명·부위·출처는 설정에서 확인하고 바꿀 수 있습니다. 첫 조회 후 24시간 캐시합니다.
- 일반 식품을 찾지 못하면 설명을 표시합니다. 사용자가 ‘연결 실패 시 샘플’을 선택한 경우에만 샘플로 대체합니다.

영양 API 키는 이 API의 활용신청 승인이 필요합니다. 예전 API만 승인받았다면 새 서비스에도 신청하세요. 인증키는 한 번 URL decode 후 requests params로 전달합니다. 키가 비면 **샘플 영양정보**로 시작합니다. 실제 레시피 사용과 실제 영양 API 사용은 별도입니다.

하루 목표는 체중 × 선택 계수(0.8 / 1.2 / 1.6 / 2.0 / 2.2), 한 끼 목표는 하루 목표 ÷ 식사 횟수입니다. [CalculatorLib 참고 방식](https://calculatorlib.com/protein-requirement-calculator)을 사용하며 건강한 성인용 추정 목표입니다. 다이어트라고 높은 계수를 자동 적용하지 않습니다. 신장질환·임신·수유·치료 식단에는 별도 전문 지침이 필요합니다.

실제 요리 재료의 비율을 유지하면서 한 끼 최대 두 요리를 조합합니다. Python이 분량과 하루 전체 재고를 계산합니다. 후보 비율과 탐색 폭이 제한된 휴리스틱이며 전역 최적해를 보장하지 않습니다. 재고 부족·요리 비율·분량 상한 때문에 목표에 못 미치면 부족량을 그대로 표시합니다.

소금·기름 기본 상한은 하루 사용 가능량 4g·20g이며 섭취 권장량이 아닙니다. 사용자가 보유 체크한 경우에만 반영합니다. 기름 9kcal/g 등 양념 영양은 **추정값**으로 표시합니다. 전체 조리 기름을 섭취한다고 계산하므로 실제 흡유량과 다를 수 있습니다. 현재 메뉴는 단백질 식품 중심 구성입니다. 표시 열량을 하루 전체 권장 섭취 열량으로 해석하지 마세요. 밥·채소를 자동으로 보유했다고 가정하지 않습니다.

## 연결 오류와 AI

설정에서 공공 API 연결 진단을 누르면 두부 한 페이지를 요청합니다. 키 없음·활용승인·HTTP·시간 초과·DNS·응답 형식 오류를 구분합니다. 오류 메시지에 인증키를 출력하지 않습니다.

OpenAI를 켜면 검색한 실제 문서에서 ID와 허용된 이유 코드를 선택해 설명을 보조합니다. 질문과 문서가 전송되며, 체중·재고 수량은 전송하지 않습니다. AI가 영양 수치나 재고를 바꾸지 않습니다. 키 없음/응답 오류 시 출처 기반 템플릿으로 대체합니다. .env는 위의 세 변수만 쓰며 LangSmith·Tavily·Redis·Upstage는 필요하지 않습니다.

`.env` 변경 후 앱/커널을 재시작하세요. 이미 터미널에 같은 이름의 환경 변수가 있으면 그것이 .env보다 우선합니다.
